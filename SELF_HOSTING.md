# АКАДЕМИЯ — установка на Spaceweb

Это версия «Наборная мастерская» без регистрации. Публикация пока не выполнялась.

## Что работает

- 18 упражнений: первые пять — одна подвижная буква, затем две, три, четыре и пять. Переход открывается после одного результата 95–100%. При успехе доступны повтор и переход; ниже 95% — только повтор.
- Плавная оценка, три режима сравнения, клавиатура, мышь и сенсорный ввод. Только прописные русские буквы; свои слова и восемь начертаний свободных шрифтов.
- Баллы +10/−3 с нижней границей ноль, награды за 1, 5, 10 и 18 пройденных упражнений. Свободные повторы и свои слова баланс не меняют.
- Семь палитр. По умолчанию «Уголь и бумага»: нейтральный угольный фон, светлые буквы, медные акценты.
- Прогресс, черновик, баллы и награды сохраняются на устройстве в localStorage. Cookie `akademiya_visitor` содержит только случайный идентификатор браузера и живёт один год. Результаты целиком в cookie не помещаются.
- Учётных записей и синхронизации между устройствами нет. При очистке данных сайта локальная практика удаляется.
- При первом открытии новой версии автоматически выбирается самый продвинутый корректный снимок предыдущей локальной практики. Старые записи не удаляются. После переноса новая запись имеет приоритет, в том числе после намеренного сброса серии.
- Статистика посещаемости по cookie: уникальные браузеры за день и месяц. Письма не содержат слов студентов, результатов упражнений или адресов посетителей.

## Подготовка файлов

На компьютере разработчика выполните `node scripts/package-selfhost.mjs`. Результат: `artifacts/spaceweb/public_html` и `artifacts/spaceweb/private`.

Сам тренажёр работает и как статический сайт: достаточно содержимого `dist`. PHP и MySQL нужны только для сбора статистики и почтовых отчётов. Для Spaceweb подготовлен комплект с включённой статистикой. Node.js на хостинге не требуется.

1. Уточните тариф и включите PHP 8.3+ с PDO MySQL. Подходит MySQL 5.7+/MariaDB с InnoDB. Настройте HTTPS.
2. Разместите публичные файлы в `public_html`, а `private` рядом с ним, вне веб-каталога. Не загружайте весь репозиторий в публичную папку.
3. Создайте базу и пользователя в панели Spaceweb. Скопируйте закрытый `config.example.php` в `config.php`.
4. Задайте полный HTTPS-адрес сервиса, реквизиты базы, секрет минимум 32 байта, почтового отправителя вашего домена и `reports.recipient` — получателя статистики. Реальные настройки в исходники не добавляйте.
5. Секрет можно создать командой `php -r "echo bin2hex(random_bytes(32));"`.
6. Для пустой базы выполните `php private/migrate.php` один раз или импортируйте `private/schema.sql` через phpMyAdmin. В новой схеме только посещения, ограничения запросов и журнал писем.
7. Проверьте реальную доставку письма через PHP `mail()` и повторный вход на сайт: результаты должны восстановиться в том же браузере без формы авторизации.

Обновление с предыдущей редакции не удаляет существующие таблицы пользователей или какие-либо записи из базы. Новые маршруты их не читают. В комплекте больше нет серверных обработчиков регистрации, кабинета и восстановления пароля; прежние адреса отвечают 404. Перед обновлением сохраните резервную копию базы и закрытого config.php.

## Отчёты по расписанию

Получатель пока не указан. Его адрес задаётся в `reports.recipient` перед включением Cron.

Согласованное время — 09:00 по Москве. Ежедневное письмо содержит предыдущий день и итог с начала отчётного месяца; отдельное месячное письмо отправляется первого числа за предыдущий календарный месяц.

При часовом поясе Cron Europe/Moscow:

```cron
0 9 * * * /ПУТЬ/К/php /ПОЛНЫЙ/ПУТЬ/private/cron.php daily
0 9 1 * * /ПУТЬ/К/php /ПОЛНЫЙ/ПУТЬ/private/cron.php monthly
```

Если планировщик работает в UTC, используйте 06:00 UTC. Путь к PHP и часовой пояс нужно сверить с тарифом. Скрипт считает периоды по Europe/Moscow; повторный запуск уже обработанного отчёта не создаёт второе письмо.

Предпросмотр без отправки: `php private/cron.php daily --dry-run`. Локальные тесты используют отдельную SQLite-базу и файловую почту. В рабочем режиме файловая отправка запрещена.

Один человек с двух браузеров или после очистки cookie может учитываться дважды. Повторные заходы одного браузера за отчётный период считаются один раз. Известные поисковые роботы фильтруются по User-Agent; это приблизительная оценка людей, а не персональная идентификация.

## Проверка

`npm test` проверяет формулу оценки, движение, переход после успешной попытки, баллы, контраст и перенос прежних сохранений. `tests/php/core.php` проверяет обезличенные отчёты и защиту от повторной отправки. `tests/selfhost.integration.cjs` проверяет API на локальном предпросмотре.

Локально проверяются SQLite и файловая почта; MySQL и реальная доставка на выбранном тарифе Spaceweb требуют проверки перед публикацией. Логику тренажёра отключение отчётного сервера не прерывает.

Справка Spaceweb: [PHP](https://help.sweb.ru/kak-izmenit6-versiyu-php-na-hostinge_138.html), [базы данных](https://help.sweb.ru/udalennyj-dostup-k-bd-mysql_929.html), [Cron](https://help.sweb.ru/planirovshik-zadach-cron_59.html), [отправка почты](https://help.sweb.ru/ne-udalos6-vyzvat6-funkciyu-mail_199.html).
